# Glossary

One definition per term. The owning module is in brackets. A new concept needs an entry in the same PR.

- **Session** [conversation]: one continuous interaction between a user and the agent, identified by an id.
- **Turn** [conversation]: one user message and the agent's complete reply, stored in time order on its Session.
- **Session store** [conversation] (`SessionStore`): the port that saves, loads, lists by user and deletes Sessions with their Turns; adapters are in-memory (tests) and SQLite.
- **Step** [runtime]: one iteration of the agent loop inside a turn (think, then optionally act).
- **Episode** [memory]: a stored summary of something that happened, kept for later recall.
- **Fact** [memory]: a small, durable statement about the user or the world.
- **Skill** [memory]: a reusable procedure the agent has learned and can replay.
- **Profile key** [memory]: an optional label on a Fact (for example `name`, `timezone`) naming a single-valued attribute of the user; compared trimmed and case-insensitively.
- **Supersede** [memory]: replace a user's active Fact with a newer Fact that has the same Profile key; the old Fact is kept, marked as superseded by the new one.
- **Active fact** [memory]: a Fact that has not been superseded.
- **Recency decay** [memory]: a factor in (0, 1] that falls with a memory's age by half-life, so recall can favour newer memories.
- **Retention** [memory]: the rules for when old memory may be forgotten: consolidated Episodes after a retention period, superseded Facts after a grace period; pending Episodes and active Facts never expire.
- **Retention policy** [memory]: the two non-negative durations (episode retention, superseded grace) that Retention rules apply.
- **Episode status** [memory]: `pending` (not yet consolidated; never expires) or `consolidated` (turned into durable memory; expires after the retention period).
- **Embedder identity** [memory] (`EmbedderInfo`): the name, version and dimension count of an embedder; stored with every vector so a model change is detectable.
- **Index entry** [memory]: a Fact or Episode stored in the vector index together with its vector and Embedder identity.
- **Vector** [memory]: an immutable tuple of finite floats an Embedder produces for a text.
- **Search filter** [memory]: optional narrowing of a vector index search or listing by kind (`fact` or `episode`), active facts only, or episode status.
- **Search hit** [memory] (`SearchHit`): an Index entry returned by a search with its cosine similarity score, best first.
- **Recalled memory** [memory] (`RecalledMemory`): a Fact or Episode returned by recall with its cosine similarity, its Recency decay and the final score (similarity times decay).
- **Fact candidate** [memory]: a fact (text and optional Profile key) proposed by the summarizer; supersede and dedupe rules decide what becomes a Fact.
- **Transcript turn** [memory]: one user or assistant message handed to the summarizer; tool activity is not representable.
- **Persona** [persona/SOUL.md]: the agent's identity, tone and values, loaded at startup and read-only to the agent.
- **Gate** [safety]: a check that must pass before an action runs.
- **Port** [each module's `ports.py`]: a `typing.Protocol` describing what a module needs from the outside.
- **Adapter** [each module's `adapters/`]: a concrete implementation of a port that talks to a vendor, a database or the file system.
- **Consolidation** [memory]: turning working memory and recent episodes into durable facts and skills.
- **Consolidation result** [memory] (`ConsolidationResult`): counts from one consolidation run: episodes consolidated, facts stored, candidates skipped (secret or already known).
- **Context builder** [runtime] (`ContextBuilder`): assembles the model's messages in a fixed order from already-fetched inputs: persona, user profile, recalled memories, skills index, history, new user message.
- **Untrusted memory** [runtime]: a recalled memory wrapped in an `untrusted_memory` block so the model treats it as data, never instructions.
- **Skills index** [runtime]: the list of all Skills (name and description) in the prompt, with the best word match for the user message loaded in full.
- **History budget** [runtime]: the character limit on past Turns in the prompt; the oldest whole Turns are dropped first.
- **Working memory** [runtime]: the context the loop holds for the current turn.
- **Budget** [runtime]: limits for a turn: steps, optional total tokens, optional seconds, and how many identical tool calls count as a loop.
- **Agent loop** [runtime] (`AgentLoop`): asks the Chat model, runs the tools it requests, feeds results back, and repeats until a final answer or a Budget limit.
- **Loop stop** [runtime] (`LoopStop`): the named reason a loop run ended: `answered`, `max_steps`, `token_budget`, `time_budget`, `loop_detected`, `truncated` or `model_error` or `safety_denied` (set by the Chat service when a Gate blocks the turn).
- **Loop guard** [runtime]: the Budget rule that ends a run as `loop_detected` when the model requests the same tool call (name and arguments) the allowed number of times.
- **Compaction** [runtime] (`Compactor`): replacing the oldest tool results in the working conversation with a short placeholder when it passes its size limit; call ids stay, so every tool call keeps an answer.
- **Session closer** [runtime] (`SessionCloser`): when a Session ends, stores its transcript as a pending Episode in the background and, every N ended Sessions of a user, runs Consolidation; failures are logged, never raised to the reply path.
- **Chat service** [runtime] (`ChatService`): starts Sessions, answers one user message (recall, context, loop, save the Turn) and ends Sessions through the Session closer.
- **Extractive summarizer** [memory] (`ExtractiveSummarizer`): the offline default Summarizer; keeps the transcript text cut to a limit and proposes no Facts.
- **Tool runner** [runtime] (`ToolRunner`): the runtime-owned port that lists tool specs and runs one tool call; safety Gates will wrap it.
- **Agent error** [shared]: an expected failure, rooted at `AgentError`, carrying a stable `code`, a message and a `retryable` flag.
- **Retryable** [shared]: whether the runtime may safely retry the failed operation; false unless the error says otherwise.
- **Adapter error** [shared]: an `AdapterError` raised at an adapter boundary; transient (retryable, e.g. timeout) or permanent (not retryable, e.g. bad API key).
- **Clock** [shared]: the source of the current time; a `Clock` port with a real `SystemClock` and a test `FixedClock`, always returning timezone-aware UTC.
- **Id generator** [shared]: the source of new opaque ids (32 lowercase hex characters); an `IdGenerator` port with a `UuidGenerator` default, which tests replace with a fake.
- **Risk level** [safety]: the classified danger of an action, which decides which gates apply.
- **Decision** [safety]: what a check returns: `allow`, `deny` or `ask` (get explicit user confirmation; treated as `deny` until that flow exists).
- **Verdict** [safety] (`Verdict`): an immutable Decision with its Risk level and a non-empty reason.
- **Classifier** [safety]: the port for a cheap, synchronous, rule-based check of a text that returns a Verdict.
- **Judge** [safety]: the port for an async, model-backed check that returns a Verdict; the composition root supplies the model.
- **Gate policy** [safety] (`GatePolicy`): one row of the table saying what a Gate checks, which Decisions it may return, what it does when its checker fails, and which fields it logs.
- **Decision step** [safety] (`decide`, `enforce`): the shared routine every Gate runs: Classifier, optional Judge for medium-risk allows, fail-closed on checker error, one log line with a subject digest; `enforce` raises `SafetyDenied` on `deny`.
- **Input gate** [safety] (`InputGate`): Gate 1; denies prompt-injection phrases in user messages and fetched content and wraps fetched content as Untrusted content.
- **Untrusted content** [safety]: fetched content wrapped in an `untrusted_content` block with its source, so the model treats it as data, never instructions.
- **Tool gate** [safety] (`ToolGate`): Gate 2; rates each tool call by Risk level (unknown tools are `high`), runs `low` and `medium` calls, and asks the Approver for `high` ones.
- **Approver** [safety]: the port that answers whether a high-risk tool call may run; none configured means deny.
- **Tool guard** [runtime] (`ToolGuard`): the runtime-owned port that decides whether one tool call may run; `GatedToolRunner` asks it before delegating to the real `ToolRunner`.
- **Memory-write gate** [safety] (`MemoryWriteGate`): Gate 3; denies secrets, planted standing instructions and injection phrases before text is stored as a Fact, Episode or Skill.
- **Write guard** [memory] (`WriteGuard`): the memory-owned port that decides whether a text may be stored; `RememberFact`, `RememberEpisode` and `GuardedSkillStore` ask it first, and Consolidation skips a denied candidate.
- **End-loop gate** [safety] (`EndLoopGate`): Gate 4; redacts secrets in the final reply, denies an empty or oversize reply, and fails open (returns the redacted reply) if a checker breaks.
- **Protected paths** [safety] (`ProtectedPaths`): the roots (`persona/`, `skills/`) the agent may not write to; the Tool gate denies write-tool calls aimed at them (a skill-management tool may write under `skills/` only) and the memory-write Gate denies text that orders such a write.
- **Text guard** [runtime] (`TextGuard`): the runtime-owned port that checks a text and returns it, possibly redacted, or raises `SafetyDenied`; the Input gate guards user messages and the End-loop gate guards replies in `ChatService`.
- **Request context** [observability]: the `trace_id`, `session_id` and `user_id` bound to the current request in context variables and stamped on every log line; null outside a request.
- **Trace id** [observability]: opaque id (from the shared id generator) that follows one request across modules in logs.
- **Session id** [observability]: id of the `Session` a log line belongs to, carried in the request context.
- **User id** [observability]: id of the user whose action caused a log line, carried in the request context.
- **Redaction** [observability]: masking secrets with the constant marker `[REDACTED]` on every log line, by sensitive key name and by value pattern.
- **Content digest** [observability]: size (characters) plus truncated SHA-256 hash logged in place of a prompt or tool output; full text is added only at DEBUG.
- **Message** [llm]: one immutable conversation entry with a role (`system`, `user`, `assistant` or `tool`); assistant messages may carry tool calls, tool messages carry a tool result.
- **Tool call** [llm]: the model's request to run a named tool with arguments; answered by a tool result carrying the same call id.
- **Stop reason** [llm]: why the model stopped: `end_turn`, `tool_use` (it asked for tools) or `max_tokens`.
- **Usage** [llm]: input and output token counts for one model call.
- **Chat model** [llm]: the `ChatModel` port; one async `complete` call turns messages into a `ChatResponse`.
- **Tool** [tooling] (`Tool`): one capability the model may call; a `ToolDefinition` (name, description, JSON schema), a Risk level and an async `run` that takes validated arguments and returns text.
- **Tool registry** [tooling] (`ToolRegistry`): holds tools by name, rejects duplicates, validates arguments against the tool's schema before running it, and exposes a name-to-Risk-level table for the Tool gate; `RegistryToolRunner` adapts it into the runtime `ToolRunner`.
- **Web fetch** [tooling] (`WebFetchTool`, `web_fetch`): fetches the text of an http(s) URL, Risk level `medium`. Only http(s), no credentials in the URL, ports 80, 443, 8080 and 8443; every hop (first request and each redirect, followed by hand, at most 5) must resolve only to public addresses, and the connection goes to the address that was checked. Limits: 15 s total, 1 MiB body, text content types only. Output starts with `[untrusted web content from <url>]` so it is treated as Untrusted content.
- **Workspace** [tooling]: the one directory (`JUNE_WORKSPACE_DIR`, default `./workspace`) the file tools may read and write; every path is resolved, symlinks followed, and must stay inside it, and `write_file` also refuses the protected roots even when they sit inside it.
